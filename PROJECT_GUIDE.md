# Huffman Text Compression Project Guide

## 1. What this project does

This is a small desktop application for compressing and decompressing **text files** with Huffman coding. It uses Python's Tkinter library for the graphical interface and a separate Python module for the compression algorithm.

The program has two workflows:

1. Choose a `.txt` file, view its text, create Huffman codes, and save a `.huf` file.
2. Choose a `.huf` file, decode it back into text, and save the result as a `.txt` file.

This is a **lossless** method: decoding a valid compressed payload should reproduce the text that was encoded. There is no web server, browser frontend, network API, or database. The frontend and backend are two Python modules running in the same application process.

## 3. Basic ideas behind Huffman coding

Huffman coding assigns a binary code to each distinct character:

- A character that appears often tends to get a short code.
- A character that appears rarely tends to get a longer code.
- No character's code is the beginning (prefix) of another character's code. This prefix-free property lets the decoder read the bits without separators.

For example, a code table might look like:

| Character | Code |
|---|---|
| `e` | `0` |
| `t` | `10` |
| `z` | `110` |
| ` ` | `111` |

The exact codes depend on the input's character frequencies and the tree built from them.

The algorithm works in these stages:

1. Count occurrences of every character.
2. Make a leaf node for each character, weighted by its count.
3. Repeatedly take the two least-frequent nodes and join them under a new parent. A min-heap makes it efficient to find those nodes.
4. Walk the finished tree: left edges mean `0`; right edges mean `1`. The path to each character is its code.
5. Replace each input character with its code to form one long bit string.
6. To decode, follow the tree one bit at a time. When a character leaf is reached, emit that character and return to the root.

## 4. How the frontend and backend connect

`frontend.py` imports the backend with `import backend`. Since both files are in the same project directory, Python can load `backend.py` as the `backend` module.

When the user presses a GUI button, Tkinter calls a frontend function. That function reads or writes the selected file, updates the GUI, and calls backend functions such as `backend.build_huffman_tree(...)` or `backend.decompress_file(...)`. The backend does not control the window; it returns data or writes output files, and the frontend presents the result.

### Compression flow

```text
Browse .txt
  -> frontend.browse_txt_file()
  -> text is read and shown in the GUI

Compress & Save
  -> frontend.run_compression()
  -> backend.build_frequency_table()
  -> backend.build_huffman_tree()
  -> backend.generate_codes()
  -> backend.encode_text()
  -> backend.get_stats()
  -> frontend writes the code table and bit string as JSON in a .huf file
  -> frontend updates the bit preview, code table, and statistics
```

### Decompression flow

```text
Browse .huf
  -> frontend.browse_huf_file()
  -> selected path is stored in the frontend

Decompress & Save
  -> frontend.run_decompression()
  -> backend.decompress_file()
  -> backend reads the JSON payload
  -> backend.rebuild_tree_from_codes()
  -> backend.decode_text()
  -> backend writes and returns the restored text
  -> frontend shows the text and reports whether it matches the
     original text still held in the current application session
```

The GUI's compression function calls the backend's algorithm building blocks itself. It does **not** call `backend.compress_file()`. Decompression, in contrast, uses `backend.decompress_file()`.

## 5. Backend: each class and function

All of the following are defined in `backend.py`.

### `Node`

Represents one node in the Huffman tree.

- `char`: the character for a leaf node; `None` for an internal node.
- `freq`: the frequency or combined frequency represented by the node.
- `left` and `right`: child nodes.

### `Node.__init__(self, char, freq, left=None, right=None)`

Initializes those four node values. A character node normally has no children; a merged/internal node has children and no character.

### `Node.__lt__(self, other)`

Compares two nodes by frequency. Python's `heapq` uses this comparison to maintain a min-heap, so the least-frequent nodes can be removed first.

### `build_frequency_table(text)`

Counts the occurrences of every character in `text` with `collections.Counter` and returns a dictionary such as `{"a": 4, "b": 2}`.

### `build_huffman_tree(freq_table)`

Builds and returns the root node of the Huffman tree:

- Returns `None` for an empty frequency table.
- Creates one leaf per character.
- Repeatedly removes the two least-frequent nodes and joins them.
- Handles a one-character alphabet by adding a parent so the character can receive a non-empty code.

### `generate_codes(root)`

Walks the tree recursively and returns a dictionary from character to bit-string code. It appends `0` for a left move and `1` for a right move. An empty tree yields `{}`; the single-character case is assigned code `"0"` rather than an empty code.

### `rebuild_tree_from_codes(codes)`

Creates a tree from the saved character-to-code dictionary. For every code, it walks or creates the corresponding left/right branches and places the character at the ending node. This allows decompression without storing the original frequencies.

### `encode_text(text, codes)`

Looks up each character's code and joins those codes together into one string of `0`s and `1`s. Empty input returns an empty string.

### `decode_text(bit_string, root)`

Reads the bit string from left to right, follows left for `0` and right for `1`, and emits a character whenever it reaches a leaf. It then starts from the root for the next character. Empty input or a missing root returns an empty string. It also has a special case for a tree that is itself a character leaf.

### `get_stats(original_text, bit_string)`

Returns a dictionary containing:

- `original_chars`: number of Python characters in the original text.
- `original_bits`: `len(original_text) * 8`.
- `compressed_bits`: number of bits in the encoded bit string.
- `saved_percentage`: percentage saved according to those two bit counts, rounded to two decimal places.

An empty original text has `0.0` percent savings to avoid division by zero.

### `compress_file(input_path, output_path)`

A backend-level convenience function that reads a UTF-8 text file, builds frequencies/tree/codes, encodes it, calculates statistics, and writes the code table plus bit string to a JSON `.huf`-style file. It returns `(stats, codes, bit_string, original_text)`.

The current GUI does the equivalent algorithm steps itself rather than calling this helper.

### `decompress_file(huf_path, output_path)`

Reads the JSON payload from a compressed file, gets its `codes` and `bit_string`, rebuilds the tree, decodes the text, writes it to `output_path` as UTF-8, and returns the restored text.

### `if __name__ == "__main__":` self-tests

When `backend.py` is run directly, this block exercises a normal sentence, a single-character input, and an empty string. It checks round trips with `assert` and prints the results. Importing `backend` from the GUI does not run these tests.

## 6. Frontend: each function and the window

All of the following are defined in `frontend.py`.

### Frontend state variables

- `selected_input_file`: path of the currently selected `.txt` file.
- `selected_huf_file`: path of the currently selected `.huf` file.
- `last_compressed_original_text`: most recently compressed text, kept in memory for an immediate lossless comparison.

These are ordinary module-level variables, not persistent storage.

### `format_char_for_display(char)`

Makes invisible characters understandable in the code table: spaces appear as `<SPACE>`, newline as `<NEWLINE>`, tab as `<TAB>`, and carriage return as `<RETURN>`. Other non-printable characters use Python's `repr`; printable characters are shown directly.

### `browse_txt_file()`

Opens a file picker for `.txt` files. If a valid file is selected, it reads it as UTF-8, saves its path in `selected_input_file`, displays the content in the original-text preview, clears previous compression output, and resets the statistics display. File-read problems are shown in a GUI error dialog.

### `run_compression()`

Runs the compression flow after the user chooses an output path:

1. Reads the original-text widget and rejects empty input.
2. Suggests a `.huf` output name based on the selected input file.
3. Calls the backend frequency, tree, code, encode, and statistics functions.
4. Writes `{"codes": ..., "bit_string": ...}` as indented JSON.
5. Saves the original text in `last_compressed_original_text`.
6. Updates the encoded-bits preview, code table, and statistics label.
7. Shows a success or error dialog.

The content is taken from the text widget, rather than re-read from the selected path. The code uses `.rstrip("\r\n")`, which removes all trailing newline/carriage-return characters from that widget content before encoding.

### `browse_huf_file()`

Opens a picker for a `.huf` file, checks its extension, stores its path in `selected_huf_file`, displays its name, and clears the old restored-text preview and lossless status.

### `run_decompression()`

Requires a selected `.huf` file and asks where to save the restored `.txt`. It calls `backend.decompress_file()`, displays the decoded text, and compares it with `last_compressed_original_text` when that in-memory value is available. The comparison is only meaningful when the original was compressed earlier in the same running application. If the `.huf` file was selected from elsewhere or the app was restarted, the GUI reports completion without that original-text comparison.

### GUI setup and `root.mainloop()`

The rest of `frontend.py` creates the Tkinter window, tabbed interface, buttons, text previews, scrollbars, Huffman code table, and status labels. Button `command=` settings connect user actions to the functions described above.

At the end, `root.mainloop()` runs only when `frontend.py` is launched directly. This event loop waits for user actions and dispatches button callbacks.

## 7. What is inside a `.huf` file?

In this project, `.huf` is a filename extension for a **JSON text file**, not a standardized binary compression format. Its payload has two fields:

```json
{
  "codes": {
    "a": "0",
    "b": "10"
  },
  "bit_string": "010..."
}
```

The saved code table lets the decoder reconstruct the tree; the bit string represents the encoded characters.

This is useful for demonstrating Huffman coding, but it is not a space-efficient production file format. The `bit_string` is stored as text characters (`"0"` and `"1"`), and the JSON code table has overhead. The displayed `compressed_bits` counts only the logical Huffman bits, not the actual number of bytes occupied by the `.huf` file. The `original_bits` statistic assumes eight bits per Python character, which is also only an estimate for Unicode text and UTF-8 files. Therefore, the displayed savings are an algorithm demonstration, not a measurement of actual file-size reduction.

## 10. Important behavior and limitations

- The application is text-only; it is not a general binary-file compressor.
- A `.huf` file selected after restarting the app can still be decoded, but the frontend cannot compare it to the original text unless that text is available in its current in-memory state.
- Trailing line breaks may be removed by the GUI before compression because `run_compression()` calls `.rstrip("\r\n")`.
- The GUI prevents empty text from being compressed, though the backend algorithm handles empty input.
- The GUI shows Huffman codes and a bit string for learning and inspection. Large files can make these previews large.
- The `.huf` JSON stores the bit string as text and does not pack bits into bytes, so it may be larger than the original file in practice.
